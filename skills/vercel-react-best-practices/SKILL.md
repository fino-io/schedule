# React 客户端性能指南

基于 Vercel React Best Practices 收敛到 React 客户端与 Vite。先解决请求等待与加载成本，再处理渲染热点，避免为了微优化增加架构复杂度。来源、固定 revision 和适配范围见 NOTICE.txt。

## 先确认环境与证据

读取实际 package.json、锁文件、构建配置、路由和受影响组件。Fino 默认脚手架为 React + Vite + React Router，但下游可以演进，不能仅凭目录名套框架。

此版本不包含 Next.js、RSC、Server Actions、SSR 缓存或 hydration 优化；这些项目需要对应框架指南。React API 按安装版本确认，React 19.0 不等于具备后续版本的 Activity 或 useEffectEvent，不为使用新 API 自动升级依赖。

先描述触发路径和瓶颈依据。运行证据可来自已有 profiling、网络记录、构建包体分析或用户提供的测量。没有运行证据时，将静态发现标为待验证线索，不声称提升了帧率或加载速度。浏览器自动化仅在用户明确要求时执行。

## 按影响处理

### 请求和加载

- 独立请求并行发起，真正依赖前序结果的请求保持顺序；结合失败语义选择 Promise.all 或局部错误处理，不用并行掩盖依赖。
- 在廉价条件检查后才发请求；避免父子 effect 串行等待可提前获得的数据。复用现有路由 loader 或查询缓存，不为消除瀑布新建请求框架。
- 查询 key、服务地址、筛选和分页保持同一作用域；作用域变化或卸载时取消或忽略过期结果。请求去重沿用已有机制，不强制引入 SWR/TanStack。
- 重组件通过现有路由懒加载或 React.lazy + Suspense 按需加载；Vite 项目不用 next/dynamic。加载和失败状态必须可用。
- 动态 import 保持构建工具可分析的路径。先检查实际产物，再调整会拉入多余代码的聚合导入；不全面禁止 barrel export。
- 预取仅服务有明确访问意图且成本合适的路径；不一律预加载全部路由或第三方脚本。

### 状态和渲染

- 从已有状态直接派生过滤结果、计数和标志，避免 effect 同步重复状态。用户事件的操作放 handler，effect 仅做外部同步并正确清理。
- 订阅尽量靠近消费者，只订阅需要的数据；确有昂贵区域才拆组件或收窄状态，避免为了防重渲染新建 Context/Provider。
- 不在组件函数内部定义另一组件，避免每次 render 改变组件身份导致 remount、焦点或状态丢失。列表使用稳定领域 key。
- 已知昂贵计算或需要稳定引用的边界才使用 memo/useMemo/useCallback；简单表达式直接计算，避免全量 memoization。尊重已有 React Compiler 配置，不重复引入编译配置。
- 基于前值更新用函数式 setState；昂贵初始计算用惰性初始化。effect 依赖保持语义正确，不以删依赖或 ref 绕过同步要求。
- 昂贵结果渲染影响输入时，评估 useDeferredValue 或 transition；输入的受控值立即更新，区分真实网络状态与 transition pending。这些 API 不减少网络请求，也不替代取消或防抖。

### DOM 与计算热点

- 避免 render 中读布局或交错 DOM 读写；优先 CSS 布局。订阅、计时器和事件 listener 随生命周期清理。
- 大列表先检查分页与实际渲染成本，必要时复用成熟虚拟列表库，保留键盘、焦点、滚动与无障碍行为。content-visibility 可减少离屏渲染，但不等同于虚拟化。
- 重复查找和大集合热点可用 Map/Set 或一次预处理；普通小数组保持可读性。不为单次查找增加缓存，不在模块级缓存用户/服务相关结果而遗漏作用域和失效。

## 修改与验证

保持现有技术栈和生成文件归属；不手改受管 API/client 或模板产物。性能调整必须保留加载、错误、分页、选择、取消与焦点行为，不把问题扩成全页重写。

运行项目现有类型检查和生产构建；Fino 标准脚手架为 `cd frontend && npm run build`。请求顺序、竞态或状态转换变化时补聚焦行为测试。模板改动在责任源修改并验证代表性生成产物。

报告瓶颈、实际改动、检查结果及测量条件。有可比较的测量时给出前后数据；仅完成构建或静态分析时，明确性能收益尚未实测。
