# Fino

让 proto、生成产物和项目实现保持一致：修改责任源，保留用户扩展点，验证受影响的行为。

## 工作方式

1. 先读项目 `AGENTS.md`、相关说明和工作区 diff；涉及契约、生成或启动时检查 `package.yaml`、`fino.yaml`，确认当前版本、服务与目标。
2. 按下表读取相关参考，定位责任源后修改。审查先收集证据；只改实现时不重新生成。
3. 契约或生成行为变化时刷新已有且受影响的目标，检查 diff 并适配项目代码；验证命令和产物见构建参考。
4. 报告改动、验证结果和未验证边界。失败时先定位首个失败层，在授权范围内修复。

| 范围 | 参考 |
|---|---|
| Proto、模型、API、HTTP 绑定、消息 | [契约](references/contracts.md) |
| RPC、领域、仓储、映射、认证、错误处理、下游调用、Go 排版 | [后端实现](references/implementation-patterns.md) |
| 页面、路由、状态、API 集成 | [前端实现](references/frontend-implementation.md) |
| 生成、工具链、启动、发布、兼容性验证、skill 更新 | [构建与验证](references/build-and-verify.md) |

只读本次涉及的参考。需要布局设计时使用可用的 `frontend-design`；浏览器自动化仅在用户明确要求时使用 `playwright`；安全审查按需使用匹配的 skill。

## 文件归属

| 责任源 | 内容 |
|---|---|
| `proto/` | API、模型、生成选项 |
| `package.yaml`、`fino.yaml` | 包身份、依赖、服务和基础设施 |
| Fino 生成器/模板、共享运行时 | 生成代码、协议绑定、布局、脚手架及通用运行行为 |
| 项目代码 | 用例、领域规则、适配器、迁移、运行配置和 UI |

- 不手改 `DO NOT EDIT` 文件或 `.fino/ir/`，也不通过删除标记改变归属。
- `SkipIfExists` 保留已有文件；`SkipIfUserCodeMixed` 仅跳过未识别为生成文件的已有文件。方法体合并另有规则，修改扩展点时保留签名、合并标记和用户逻辑。
- 归属不明时查当前版本生成器，必要时在同契约、配置和目标的临时副本中比较；不覆盖已演进项目。
- 通用修复放生成器或运行时，验证代表性产物后再移除项目变通；业务策略、服务名、端口及事故记录留项目。

## 约定与工作项

遵守归属、分层、协议、安全和兼容性边界；格式及日志默认值服从项目规范。可选约定按项目选择，不照搬示例改写已有 API、字段编号或技术栈。说明以中文为主，代码符号、路径、配置键和协议名称保持原样。

工作项遵循 `.fino/issues/README.md` 和 `ISSUE-*.md`；旧项目仍用 `.fino/bugs/` 时沿用原协议，不擅自迁移。复现、修复及验证证据写回原工作项；无法复现说明条件，必要验证未通过不标 `resolved`，延期使用 `backlog` 或项目约定状态。只启动必要服务，只清理本次启动且未被其他任务使用的资源；工作项本身不要求新增模型或 RPC。
