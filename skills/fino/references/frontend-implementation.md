# 前端实现

用于项目自有页面、路由、状态和 API 集成。先检查 `package.json` 脚本、路由器、应用外壳、API 入口与受影响页面，沿用项目框架和依赖。已有页面可提供模式，不整页复制，也不因 `app/` 目录名推断框架。

## 归属与职责

| 内容 | 归属与改动位置 |
|---|---|
| `frontend/generated/` | 受管的客户端/路由契约，修改 proto 或生成器 |
| API Console/Issues 页面与共享工具页样式 | 当前模板在 `frontend/app/console/`、`frontend/app/issues/`；`frontend/app/tool-shell.css` 也是受管样式。维护旧项目时按文件头/对应版本生成器识别旧的 `app/debug/`、`app/bugs/`，不在新项目恢复旧路径 |
| `router.tsx`、`app/app-layout.tsx`、`app/globals.css`、`app/theme-toggle.tsx` 等外壳 | 默认脚手架创建后保留，项目可定制 |
| 页面、组件、`frontend/api/`、`frontend/lib/` | 项目代码，沿用实际目录，不强制把 `components/` 下的页面搬到 `app/` |

受管文件不能手改；`SkipIfExists` 的项目扩展点可以修改。通用外壳行为（路由加载、主题 token、响应式导航、无障碍交互）确需跨项目修复且在范围内时，修改 `frontend/generator/templates/frontend/` 并验证代表性产物。项目导航、上下文、业务 API 和领域页面留项目；复用布局 class 不代表功能应上移模板。模板更新也不能强制覆盖已定制外壳。

- 路由器组合路由、懒加载和兜底；应用外壳统一共享导航、主题和路由出口；页面组合完整工作流。
- 请求协调、转换、复杂展示放功能旁的聚焦模块；多个调用方需要同一行为时才提取共享组件。不搭建空分层或通用页面/schema 引擎。
- 项目 API 入口导出生成客户端并配置共享请求，功能请求 helper 靠近调用方，环境设置放配置边界；页面不重写传输逻辑。
- 共享样式表放 reset、语义 token 和外壳样式；功能样式并置，用功能 class 或既有 CSS Module 限定作用域，不为单页覆盖全局元素。

## 类型与函数格式

- 优先用生成的请求/响应类型；仅有路由元数据或无类型客户端时，在一个边界定义与契约一致的最小类型。确需转换才增加展示模型。
- 除非契约证明数值安全，大整数 ID 保持字符串。区分缺失与 false/0，在命名明确的适配器统一时间戳/枚举；不在 JSX 重复转换。
- 用有类型的函数组件、明确 props、语义清楚的 handler 和普通 helper。effect 仅做外部同步；可直接派生的值不另存状态。memoization 只用于已知开销或确需稳定引用的地方。
- 遵循既有 import、命名和格式；按职责而非行数拆分，避免臆测接口、配置注册表和单行转发 hook。
- 优先复用现有依赖。路由、解析、表单、表格、图表等成熟能力优先评估维护良好的库；不为简单展示加库，不替换现有技术栈。

按职责阶段用空行分段：局部常量/类型 → hook 与远程同步 → 事件处理 → 展示转换 → JSX return。保持相关语句相邻，不将请求、状态更新和渲染挤成连续大块，也不逐行插空行。多行 JSX 属性按可读性分行，复杂参数/展示计算先绑定局部变量。此约定用于项目自有组件与 helper；受管页面应改源模板，不手工格式化产物。

## 状态、请求与作用域

- 临时状态靠近责任组件；需刷新保留/共享链接的导航状态放路由或搜索参数。真实跨页面需求才引入共享 store，状态提升到最近的共同责任方。
- 分开远程数据、编辑草稿和展示状态；过滤行、计数、选中对象从规范源派生，不同步重复副本。编辑组件按资源标识初始化草稿，后台刷新保留输入；资源切换或显式重置时才重新初始化。
- 复用现有查询/缓存机制；有重复读取、缓存和刷新需求时优先使用成熟查询库。共享查询定义靠近功能 API，多个调用方复用同一份定义；TanStack Query 项目可用 `queryOptions`，不再用 context 或本地 state 镜像查询数据。
- Query/cache key 包含资源作用域和影响响应的筛选、排序、分页参数；有范围失效需求时按资源层级组织 key。缓存时效由业务决定，不把单个项目的时长写成全局约定。查询取消信号传递到生成客户端；直接 effect 请求须在作用域变化/卸载时取消或忽略过期响应，防止覆盖新选择。
- 多服务请求先解析服务专用运行时 base URL，再回退全局默认；所选服务、base URL、请求元数据和 query/cache key 保持一致，不能写死开发端口。
- 过滤、排序、分页贯穿 API，查询作用域变更重置页码/游标。仅完整且有界的数据可本地过滤，已加载一页不等于全量。
- 写入成功后用返回值更新对应缓存，或失效受影响的资源和列表查询；失效范围覆盖实际依赖，避免刷新其他作用域。失败保留草稿，进行中防重复提交；写入错误与读取错误分开，区分首次加载、刷新、空结果、请求失败。
- 只持久化必要状态并使用现有工具；存储不可用/浏览器能力缺失时有明确回退，不破坏页面其他功能。

## 样式与验证

背景、文字、边框、强调色和反馈使用语义 CSS 变量；支持主题时在根节点切换 token 并跨页复用。具体品牌、配色和尺寸留项目，布局/交互使用可用的 `frontend-design`。

按[构建与验证](build-and-verify.md)执行前端构建或生成器验证；重要状态转换和请求竞态补行为测试。说明未验证的视觉及交互边界。
